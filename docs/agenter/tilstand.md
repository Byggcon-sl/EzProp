# Tilstand for agentlaget

Oppdateres av prosjektlederen etter hvert steg. Leses først i hver kjøring. Alle steg tåler å kjøres to ganger. Filen holdes kort: bare det som gjelder nå. Historikken til og med 10.11.2026 står i `docs/agenter/arkiv/tilstand-til-2026-11-10.md` (der står også små funn fra tidligere leveranser, «liten oppgave (v)–(ad)»).

**Autonom modus: på** (Ståle 04.11.2026, til han sier fra: «Jeg synes det fungerte så bra at du kan kjøre videre på autonom utvikling igjen»). Ingen varsler, ingen spørsmål, ingen «Venter på Ståle». Agentene avgjør selv ut fra researchen og fører beslutningene i `docs/09-apne-sporsmal.md` («Avgjort av agentene mens Ståle var borte», neste nummer etter det høyeste A-nummeret, nå A199). Det bare Ståle kan gjøre, samles under «Trenger Ståle når han er tilbake». Se «Autonom modus» i `CLAUDE.md`.

**Hovedmål (Ståle 10.11.2026):** best mulig system for de ansatte, KI først og KI i bunnen, og færre reklamasjoner. 50 % mindre tid er ikke lenger hovedmål. Se `CLAUDE.md`.

**Ståle 10.11.2026 (i chat):**
- S1, S2 og S3 er gjort: testmiljøet i Azure virker (bekreftet 12.11.2026 med første vellykkede utrulling til `rg-ezprop-test2`, database i Norway East), prøvene på ekte iPad er kjørt, ADR 0004 (egenbygd synk) er godkjent, og fagråd runde 1 er godkjent. De tre fagspørsmålene er besvart (spørsmål 59 i `docs/09-apne-sporsmal.md`, ført inn i PR #128).
- KI-leverandør er Anthropic, og Ståle har API-nøkkel. Anthropic-adapteren bygges bak KI-porten (ADR 0006) og kobles til secret `ANTHROPIC_API_KEY` via `readSecret`. Beslutningsnotatet (siste punkt i 2a-1) må si om behandlingen kan skje i EU/EØS.

## Trenger Ståle når han er tilbake

Kortlisten står i `docs/07-utviklingsplan.md` under «Venter på Ståle» (S4–S8). I tillegg:

- **KI-leverandør (S8): Anthropic-adapteren er klar** (når PR-en for `fase2a-ki-leverandor` er merget). Les `docs/beslutningsnotat-ki-leverandor.md` (rundt to sider).
  - **Før nøkkelen brukes med ekte data:** velg EU/EØS-vei (Anthropic direkte er utenfor EØS; EU-region krever Amazon eller Google), godta eller signer databehandleravtalen, svar på spørsmål 54–58 og 73, og vurder forslag 64 (tak på KI-bruk). Til da lages tilkoblingen `anthropic` ikke for en organisasjon med ekte data. Velg også leverandør for tale til tekst før fase 2b (anbefalt: Microsoft Azure tale i Norge).
  - **Slik legger du inn nøkkelen (testmiljøet, oppdiktede data, koster penger):** 1) GitHub → repoet → Settings → Secrets and variables → Actions → New repository secret. Navn `ANTHROPIC_API_KEY`, verdi: nøkkelen. Aldri i chat, e-post eller repo. 2) Kjør utrullingen til testmiljøet på nytt. 3) Tilkoblingen lages som admin i testmiljøet (det finnes ingen skjerm for det ennå; si fra til agentene, så lager de den for deg med rettigheten til admin): port `ai`, leverandør `anthropic`, hemmelighet `ANTHROPIC_API_KEY`, modell (modell-id-en fra Anthropics modelliste, bare i tilkoblingen), funksjoner (tom liste til evalueringen er kjørt) og pris i kroner per million tokens inn og ut (se prisdelen i notatet). Den falske tilkoblingen slettes mykt først (én tilkobling per port). 4) KI slås på for organisasjonen (`ai.enabled`). Slås av igjen med samme bryter.
  - **KI er ikke slått på for noen funksjon** før evalueringssettet er kjørt mot den ekte modellen og funksjonen har bestått. Evalueringsprogrammet tar i dag bare den falske leverandøren og må utvides først (liten oppgave for agentene). Selve kjøringen mot den ekte modellen koster litt penger, så den gjøres først når Ståle har sagt ja. Deretter føres funksjonen inn i listen over funksjoner på tilkoblingen.
- **Synkprøven i Azure kan ryddes** (etter at PR-en som fjerner PowerSync og ElectricSQL er merget): de fire GitHub-secrets for synktjenestene og variabelen `ENABLE_SYNC_TRIAL` kan slettes (`docs/drift/testmiljo-azure.md`). Synkbryteren var aldri på, så ingenting må slettes i Azure.
- **Nøkkelboksen for hemmeligheter (ADR 0005):** sett GitHub-variabelen `ENABLE_KEY_VAULT` til `true`, kjør utrullingen og sjekk hakemerkene i App Service (`docs/drift/testmiljo-azure.md`, «Nøkkelboks for hemmeligheter»).
- **E-post via Microsoft 365 i testmiljøet (PR #64, A44):** de fire secretene `MS_GRAPH_TENANT_ID`, `MS_GRAPH_CLIENT_ID`, `MS_GRAPH_CLIENT_SECRET` og `MAIL_FROM`, og én ekte innlogging i testmiljøet (`docs/drift/testmiljo-azure.md`).
- **Fillagring i Azure (PR #62):** lagringskonto i Sweden Central (koster penger), privat container, og bekreft at databehandleravtalen for Azure dekker den.
- **Tidsmåling (A121, A123):** legg inn tallene fra målingen i IVIT på `/statistikk/tid`, og drøft målingen med de ansatte først (arbeidsmiljøloven kapittel 9).
- **Personvernspørsmålene om KI** (54–58 i `docs/09-apne-sporsmal.md`) før ekte KI brukes med ekte data.
